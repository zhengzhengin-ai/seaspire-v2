# 1. Project Overview

## 1.1 Purpose

Seaspire v2 is the official corporate website of Seaspire.

The website represents the company's:

* Corporate identity
* Product capabilities
* Manufacturing strengths
* International business credibility
* Customer communication channels

The website is designed primarily for B2B seafood buyers, importers, restaurant groups and food service partners.

---

## 1.2 Primary Goals

The project is designed around the following objectives.

### Professional Branding

Build a modern corporate image suitable for international seafood trading.

### Product Presentation

Present seafood products with consistent visual quality.

### Business Trust

Strengthen customer confidence through professional design, certifications and company information.

### Scalability

Maintain an architecture suitable for long-term expansion.

### SEO

Provide an SEO-ready foundation before deployment.

### Future Expansion

Prepare for future CMS integration, multilingual support and digital marketing.

---

## 1.3 Development Philosophy

Seaspire v2 follows several core principles.

### Architecture First

A stable architecture is more important than rapid feature development.

### Consistency First

Consistency always has higher priority than visual creativity.

### Reusability

Reusable components should be preferred whenever possible.

### Maintainability

Every decision should reduce future maintenance costs.

### Simplicity

Avoid unnecessary complexity.

# 8. Component Rules

## One Component

One responsibility.

Never combine multiple business purposes into one component.

---

## Shared Component First

Before creating a new component,

always evaluate whether an existing component can be reused.

---

## Shared Components

Shared components include.

```text
Navbar

Footer

Hero

PageHero

CTA

SectionHeading

ProductCard

ContentCard
```

---

## Page Components

Page-specific layouts should remain inside

```text
app/
```

They should not be promoted into shared components unless reused.

---

## Component Communication

Data should flow downward.

```text
Page

↓

Component

↓

Child Component
```

Avoid unnecessary deep prop drilling.

---

# 9. Component Freeze Policy

After UI acceptance,

shared components become frozen.

Current frozen components.

```text
Navbar

Footer

Hero

PageHero

CTA

SectionHeading
```

Components under observation.

```text
ProductCard

ContentCard
```

These may continue to receive refinements until full project UI acceptance.

---

## Modification Rules

Shared components should only be modified when.

* The change benefits the entire website.
* The change improves maintainability.
* The change is requested by project owner.

Otherwise,

page-level adjustments should be preferred.

---

## Asset First Principle

Whenever possible,

modify image assets instead of component dimensions.

Priority order.

```text
Image

↓

Content

↓

Page CSS

↓

Shared Component
```

Shared components should be the last option.

---

## Layout Stability

Layouts should remain stable.

Images should adapt to layouts,

not the opposite.
